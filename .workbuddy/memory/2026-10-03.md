## 接入 GitHub 镜像 + Gitee→GitHub 自动同步

- 新增远程 `github` → https://github.com/mml-hrb/astrbot-plugin-dota2matches.git ；
  `origin` 仍是 Gitee（`gitee.com/Mml3289469099/astrbot-plugin-dota2matches.git`）。
  **分工：Gitee 是主仓库，GitHub 是只读镜像。** 本地日常 `git push` 不带参数 → 推 Gitee。
- 新增 `.github/workflows/sync-from-gitee.yml`：每 10 分钟（`*/10 * * * *`，UTC）+ `workflow_dispatch`
  手动触发；`fetch-depth: 0` 拉全历史，`fetch --tags --force --prune`，
  主分支 `git push github '+refs/remotes/gitee/main:refs/heads/main' --force`；
  其他分支与标签单列一步且 `continue-on-error`，不因某个本地独有分支把任务刷红。
  `concurrency: sync-from-gitee` 防定时与手动撞车。结尾写 GITHUB_STEP_SUMMARY。
- Gitee 仓库公开，所以**默认不需要凭据**。留了条件式 `GITEE_TOKEN`：
  `if: ${{ secrets.GITEE_TOKEN != '' }}` 才 `git config http.https://gitee.com/.extraheader`。
  这里刻意不用无条件写法——secret 为空时会生成一个无效 basic 头，把公开拉取也搞挂。

### 本机网络坑（重要）

环境里有 HTTP 代理 `127.0.0.1:5993`（`http_proxy`/`https_proxy` 均指向它）。
该代理对 **github.com 443 极不稳定**：大量 `CONNECT tunnel failed, response 502`
和 `schannel: failed to receive handshake`，而 `api.github.com`、gitee.com 基本正常。
- `git push github` 连续失败 5 次、轮询 12 次 ls-remote 全挂；
  最终在**第 12 次、约 4.5 分钟**后台重试时成功。
- 结论：往 GitHub 推东西时**必须带重试循环**，单次失败不代表仓库/凭据有问题。
- 写重试循环的坑：`git push ... | tail -8 && break` 里管道会让退出码变成 `tail` 的 0，
  循环无条件只跑一次。正确写法是重定向到文件再判 `if git push ... >/tmp/p.log 2>&1; then`。
- 另：沙箱里 `run_in_background` 的长任务别用 `sleep` 轮询，会被 SIGTERM 掐掉，
  直接后台跑 + `TaskOutput` 收结果。
