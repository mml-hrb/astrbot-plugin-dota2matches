# astrbot_plugin_dota2 · Dota2 数据查询助手

基于 [STRATZ](https://docs.stratz.com/) + [OpenDota API](https://docs.opendota.com/) 双数据源的 AstrBot 插件，提供 Dota2 战绩查询与 AI 复盘分析能力。默认以 STRATZ 为主源，失效时自动降级到 OpenDota。

## 功能

| # | 能力 | 指令 |
|---|------|------|
| 1 | 绑定玩家（昵称 / 32 位 account_id / 64 位 SteamID） | `/d2 绑定 <目标>`、`/d2 解绑` |
| 2 | 按玩家查询战绩 | `/d2 战绩 [场次] [目标]` |
| 3 | AI 分析近期表现与打法风格（默认最近 20 场，场次可调） | `/d2 分析 [场次] [目标]` |
| 4 | AI 深度复盘单场比赛（走势 / 质量评估 / 十人点评） | `/d2 单场 <比赛ID> [目标]` |
| 5 | 监听玩家，比赛结束且详细数据就绪后自动推送分析，支持解绑 | `/d2 监听`、`/d2 取消监听`、`/d2 监听列表` |
| 6 | **自然语言识别**：不用记指令，直接说人话就能触发（需带唤醒词 `dota2助手`） | 见下方「自然语言」 |
| 7 | **催解析并等待**：单场复盘遇到未解析的局，自动催解析、每分钟检查一次、最多等 10 分钟 | `/d2 单场 <比赛ID>`、`/d2 催解析 <比赛ID>` |
| 8 | **双数据源自动降级**：STRATZ 为主、OpenDota 为后备，主源失效自动切换 | `/d2 数据源` |

辅助指令：`/d2 帮助`、`/d2 我的`、`/d2 绑定列表`、`/d2 资料 [目标]`、`/d2 英雄 [目标]`、`/d2 数据源`。

## 自然语言（免指令）

不用背指令，直接说人话即可触发对应功能。**默认需要在消息里带上唤醒词 `dota2助手`**：

```
dota2助手 帮我看看我的战绩              → 战绩查询
dota2助手 分析一下天鸽最近的发挥          → AI 近期分析
dota2助手 这局 8993438099 复盘一下       → 单场深度复盘（未解析会自动催解析并等待）
dota2助手 催一下 8993438099 的解析       → 只催解析
dota2助手 最近 20 把打得怎么样           → 按 20 场分析
dota2助手 天鸽的英雄池 / 我段位多少       → 英雄池 / 玩家资料
dota2助手 把天鸽加入监听                 → 添加监听
dota2助手 取消全部监听                   → 取消监听
dota2助手 监听列表                      → 查看本会话监听
```

识别不出指令时，插件会**带着本会话的真实数据接着聊**（闲聊兜底，见下）：

```
dota2助手 对比一下目前监听的几个人谁最菜    → 读监听名单 + 各人近期胜率/KDA/GPM
dota2助手 我们群谁最强                     → 同上，给出排序与依据
dota2助手 我想转辅助，该怎么练              → 结合你的英雄池与近期表现给训练建议
dota2助手 天鸽最近状态如何                 → 点名某人，读他的近期战绩
```

设计要点：

- **必须带唤醒词才响应**（`nlu_require_keyword` + `nlu_keyword`，默认 `dota2助手`）：
  自然语言入口监听会话里的**所有**消息，不加这道闸门就会抢答其他插件（以及群里
  其他人闲聊）的对话。消息里没有唤醒词时插件**完全不介入**，消息照常交给默认大模型。
  忽略大小写，中英文交界处多打空格也认（「Dota2 助手」）。
  想改词就把 `nlu_keyword` 改成顺口的形式；留空则回落到默认值。
- **唤醒词等价于一次点名**：写了唤醒词就不再额外要求 @ 机器人，避免双重门槛；
  只有 @ 而没写唤醒词的消息仍会被挡掉；
- **确认 / 取消不需要唤醒词**：直接回「确认」「取消」即可，也可以写
  「dota2助手 确认」——两种写法都认（这是对上一轮已授权操作的收尾，不必重复点名）；
- **不抢答 ≠ 只是「不说话」**：AstrBot 的插件 handler 只要调用了
  `event.stop_event()`，同一事件上**排在它后面的所有其它插件 handler 与默认
  大模型都会被跳过**（`StarRequestSubStage` 遇到 `is_stopped()` 直接 `break`）。
  所以自然语言入口这个全局监听器**只在真的接管消息时才终止传播**：没通过闸门
  就原样放行。否则会出现「插件一开启，正常对话和其他插件全都没反应」——
  这比抢答更严重。
- **没写唤醒词的闲聊不会被拦截**：不带唤醒词的消息（「在吗」「中午吃什么」）
  插件完全不介入，原样交给 AstrBot 默认大模型正常回复，绝不抢答；
- **写了唤醒词但没识别出指令 → 带数据接着聊**（`nlu_chat_fallback`，默认开）：
  唤醒词是用户对插件的**明确点名**，此时把消息扔回默认大模型是浪费——默认
  大模型看不到本会话的监听名单、绑定关系与战绩数据，只能反问，或者干脆编几个人名。
  所以插件改为自己来答，并且把数据一起带上：
  - 本地数据（监听名单、绑定名单）**总是**注入，读本地文件、零网络开销，闲聊秒回；
  - 网络数据（各人近 N 场胜率/KDA/GPM、提问者的英雄池）**按需**注入——只有问题里
    出现「谁 / 对比 / 战绩 / 练什么 / 位置」这类信号，或点名了某个被监听者时才去拉，
    避免每句闲聊都打十几个接口；
  - 上下文里除了原始数据，还给出一个按胜率/KDA/GPM 加权的「参考分」当锚点，同时
    明确要求模型：**不许编造数据**，且 GPM 受位置影响（辅助天然偏低），
    不能只看 GPM 判强弱；某人数据取不到时如实标注；
  - 想省 token 或不需要这个能力，把 `nlu_chat_fallback` 关掉即可，
    这类消息会回到默认大模型手里（关掉后就不再有「带数据」的回答）。
  - 注意这条通道**不继承 AstrBot 的多轮对话上下文**（它是插件自己发起的单次调用）；
    要结构化、可复现的结果，还是用 `/d2 分析`、`/d2 单场` 这类指令更稳。
- **群聊默认需要 @ 机器人**：避免群里别人随口一句话就触发查询、白耗 API 配额，
  可在配置中关闭（`nlu_group_require_at`）；
- **敏感操作先确认**：「绑定 / 解绑 / 添加监听」在自然语言触发时会先回一句确认，
  你回复「确认」才真正执行，「取消」则不执行（`nlu_confirm_sensitive`）；
- **不依赖大模型**：规则引擎免费且即时；如需更强的口语理解，可开启
  `nlu_llm_fallback`，规则没把握时额外调用一次模型做意图分类。

自然语言入口与指令入口走的是**同一套实现**，因此行为、权限、输出格式完全一致。

## 安装

1. 把 `astrbot_plugin_dota2` 目录放到 `AstrBot/data/plugins/` 下；
2. 在 AstrBot WebUI 的「插件管理」中重载插件；
3. 打开插件配置，按需填写（可选）OpenDota API Key 与 HTTP 代理。

依赖：`httpx`（AstrBot 本体已内置）。

## 指令详解

### 绑定

```
/d2 绑定 天鸽                  # 昵称（走 OpenDota 搜索）
/d2 绑定 86745912              # 32 位 account_id
/d2 绑定 76561198047011640      # 64 位 SteamID
/d2 绑定 https://steamcommunity.com/profiles/76561198047011640
```

绑定按「会话 + 用户」维度保存，群聊里每个人可以各自绑定自己的账号。
昵称搜索命中多个同名玩家时，插件会列出候选并提示改用账号 ID。

`/d2 解绑` 会同时清理该账号在当前会话下的监听。

### 查询

```
/d2 战绩                       # 自己的最近 20 场
/d2 战绩 50                    # 自己的最近 50 场
/d2 战绩 20 天鸽                # 指定玩家的最近 20 场
/d2 资料 86745912               # 玩家资料、段位、生涯胜率、常用英雄
/d2 英雄                        # 英雄使用统计
```

### AI 分析（近期表现）

```
/d2 分析                        # 默认最近 20 场
/d2 分析 40                     # 最近 40 场
/d2 分析 20 天鸽                # 指定玩家
```

生成的报告包含：一句话结论 → 近期状态走势 → 打法风格画像 → 数据亮点与短板 → 可执行的改进建议。

数据侧会聚合：胜率与最近 10 场胜率、连胜连败、前后半段胜率对比（判断状态趋势）、
场均 K/D/A 与 KDA、GPM/XPM、补刀/反补、英雄/建筑伤害与治疗、分路分布、游走局数、
英雄池胜率、单排/组队比例，并附上完整的逐场明细表。

### AI 复盘（单场比赛）

```
/d2 单场 8989601141
/d2 单场 8989601141 天鸽        # 指定重点点评的玩家
```

报告包含：比赛走势复盘 → 比赛质量评估 → 关键数据对照 → 焦点玩家点评 → 其余选手点评 → 关键转折点。

喂给模型的原始数据包括：

- 对局基础信息（时长、模式、比分、一血、买活、region/cluster/patch、BP 顺序、塔与兵营存活、双方平均段位、真人玩家数、联赛标记）
- 逐分钟经济差与经验差采样、最大领先时间点、经济领先易手次数、翻盘深度（胜方曾落后的最大幅度；数据源给了 ``comeback`` / ``stomp`` 时直接引用官方口径）
- 关键事件时间轴（推塔、肉山、不朽盾、信使、买活）
- 团战列表：起止时间、双方各自阵亡人数、**双方阵亡名单（谁先死）**、双方经济净变化，以及焦点玩家在每场团战里的伤害/治疗/击杀/买活/金银经验变化
- 十人完整数据（等级、KDA、净经济、GPM/XPM、补刀、伤害、参团率、控制、真假眼、出装含背包与中立物品）
- 十人进阶数据：**经济来源构成**（补刀/击杀英雄/野怪/建筑/赏金符…）、阵亡+复活耗时占比、已花费与余额、多杀与最长连杀、击杀建筑/肉山、堆野/吃符/信使击杀、打点次数
- 十人输出/承伤构成（按技能、按目标单位）、**英雄间伤害矩阵**（对谁造成最多伤害 = 谁针对谁）、技能与道具使用次数、单次最高英雄伤害
- **发育节奏节点对比**：十人在第 10/20/30/40 分钟的累计金钱/补刀/经验，可横向比发育速度
- **视野与守卫**：每人插眼数量与时间跨度、被敌方清除的数量
- 焦点玩家的深入数据：补刀效率、逐分钟发育曲线（经济/经验/补刀/反补/英雄伤害/堆野/治疗，每 3 分钟采样）、经济与经验来源分解、输出与承伤构成、对英雄伤害明细、击杀时间线与被谁击杀、连杀记录、技能加点顺序、技能施放对象与命中次数、中路/道具使用、中立物品获取时间线、关键装备与全部装备时间线、买活时间、视野明细
- 焦点玩家近 10 场的整体状态（用于判断本场是正常发挥还是异常）

> 只有**已解析**的比赛才有上面加粗的那批数据。未解析时这些小节省略，并且提示词会
> 明确告诉我们「缺少逐分钟/团战/出装数据，别对具体时间点的决策下结论」——
> 数据没给就标注「数据未提供」，模型被要求不许编造。
>
> 说明：技能加点顺序用的是解析产物里的 ``ability_upgrades_arr``（一串技能数字 ID），
> 需要 OpenDota 的 ``/constants/ability_ids`` 把它翻成技能名；拿不到该常量表时这一节
> 会自动省略，不会喂一串看不懂的数字。

### 催解析 + 等待解析（单场复盘）

**OpenDota 收录一场比赛 ≠ 解析完这场比赛的录像。** 只有解析完成才有逐分钟经济、
团战、出装这些数据，而 AI 复盘的价值几乎全在这里。未解析的局只有 KDA、时长、
英雄这类基础字段。

`/d2 单场 <比赛ID>` 在遇到未解析的局时会自动走「催 + 等」：

```
/d2 单场 8995419388          # 未解析 → 自动催解析并等待（每分钟检查，最多 10 分钟）
/d2 单场 8995419388 skip     # 不等，直接用基础数据出报告
/d2 催解析 8995419388         # 只催 OpenDota 解析，不等结果
```

完整流程：

1. 拉取比赛数据，用 `od_data.has_parsed`（或玩家级 `gold_t` 是否填充）判断是否已解析；
2. 未解析时立即向 OpenDota 提交解析申请（`POST /request/{match_id}`，按 10 倍额度计费），
   并回一条说明消息告诉你「已排队、每分钟检查一次、最多等 10 分钟」；
3. **等待在后台任务里进行**，不占用对话——你可以继续发别的指令；
4. 之后每 `parse_check_interval`（默认 60 秒）检查一次，每次检查都播报当前状态
   （已等待多久 / 还剩多久 / 卡在哪一步）；期间大约每 5 分钟补交一次解析申请
   （OpenDota 的解析任务偶有丢单）；
5. 解析完成后，**自动把完整复盘报告推送到发起指令的会话**；
6. 超过 `parse_wait_timeout`（默认 10 分钟）仍未解析：发一条明确的通知并放弃这一场，
   **不会影响其他任务**，并提示你可以稍后重试或用 `skip` 看基础数据版。

为什么等待要放到后台：AstrBot 的流水线是「洋葱模型」——handler 每 `yield` 一条结果，
后续阶段（含默认大模型）就会整体执行一次。如果 handler 直接挂在那里等十分钟、
逐分钟 `yield` 进度，等于给流水线制造十次执行机会，默认大模型就会插嘴。
后台任务用 `context.send_message` 主动推送则完全没有这个问题。

### 监听

```
/d2 监听                        # 监听自己绑定的账号，推送到当前会话
/d2 监听 86745912               # 监听指定账号
/d2 监听列表                     # 查看本会话的监听与等待中的分析
/d2 取消监听 86745912
/d2 取消监听 全部                # 取消「你自己添加」的全部监听
```

`取消监听` 只能操作自己添加的监听；`admin_users` 中列出的用户（以及 AstrBot 自带
管理员）可以取消本会话内他人的监听。单会话监听数量受 `watch_max_per_session` 限制。

工作流程：

1. 添加监听时记录当前最新比赛作为**基线**，只有之后的新比赛才会推送（不会补推历史）；
2. 后台按 `watch_interval` 轮询被监听玩家的比赛列表；
3. 发现新比赛后，等数据源把它收录（比赛刚打完可能还查不到），**一被收录就推送**；
4. **一局只生成一份短评**并推送到所有相关会话：短评是「胜负 + K/D/A + 近期战绩对照」
   的 2~4 句话，不 `@` 任何人；若这一局有多位被监听的玩家在打，短评里会逐一点到
   （说明：短评只要胜负与 K/D/A，这些字段比赛一被收录就有，因此**不再等录像解析**）。

推送长什么样：

```
🏁 比赛回顾 · 8995536921
2026-09-14 21:03（3 分钟前） · 时长 23:56 · All Pick
天辉 37 : 11 夜魇 · 天辉获胜
👤 焦点玩家：钢板 · Luna · 2/12/5 ❌负

这局钢板拿了个 Luna 被打成 2/12/5，23 分钟就结束了比赛，输得比较干脆。
对照他最近 10 场 40% 胜率、场均 KDA 2.8 的水平，这一局死亡数直接翻了三倍，
明显不在状态。（想要完整复盘用 /d2 单场 8995536921）
```

要看深度复盘（走势、质量评估、关键数据对照、十人点评）请用 `/d2 单场 <比赛ID>`，
那条链路仍然会「催解析 + 等解析」并调用完整报告提示词。

投递语义与几个容易踩的点：

- **至少一次投递**：`last_match_id` 只在推送成功之后才落盘。重启、崩溃或推送失败
  都不会让比赛永久丢失，下一轮会重新发现并补推；推送失败的会话保持原基线。
- **补推有上限（掉线不会无限重试）**：某个会话连续 `watch_max_deliver_attempts` 次
  （默认 10）没把消息发出去，就放弃这个会话的这场推送、推进它的监听进度，
  不再重试。计数按「会话 × 比赛」分别计，其他正常会话照常推送、不受牵连；
  中途恢复并成功送达会清零计数。这样 bot 账号掉线时后台重试有限次就停，
  不会一直空转。
- **一局只点评一次**：同一场比赛若有多位被监听的玩家参与（群里几个人各自关注不同的人，
  恰好撞上同一局时很常见），只生成**一份**短评——短评里为每位焦点玩家各点一句，
  同一个群聊只收到一条推送。比赛详情也只拉一次，不会重复消耗配额。
- **不 `@` 订阅人**：推送是「比赛结束的自动播报」，静默发到会话即可。
  早期版本会 `@` 该会话里所有添加过监听的人（配置项 `watch_notify_at`），已整体移除。
- **不看录像解析**：短评只用胜负与 K/D/A，因此不提交解析申请、不等待解析，
  比赛被收录后一两分钟内就能发出——这也是它比旧版「自动战报」快的原因。
  需要解析产物的用户自己走 `/d2 单场 <比赛ID>`。
- **重试节拍**：等待收录的重试有独立的 30 秒节拍（不是 `watch_interval`），
  `next_try_at` 会被按时兑现。
- **权限**：`取消监听` 只能取消自己添加的监听；`admin_users` 中列出的用户
  （以及 AstrBot 自带管理员）可以取消本会话内他人的监听。单会话监听数量受
  `watch_max_per_session` 限制。
- **被踢出群 / 被拉黑会自动取消监听**：向某会话发消息时，若平台明确返回
  「bot 已不是群成员」「已被拉黑」「群聊不存在」「账号被封禁」之类错误，
  说明这个会话再也不可能收到推送，插件会自动删除该会话下的**全部**监听，
  并丢弃它的待推送条目——否则后台会一直白跑、白花大模型配额。
  判定从严：只认明确语义的报错，网络超时、连接重置、5xx 这类普通故障
  **不会**误删（误删监听不可逆，宁可漏判——漏了还有上面的失败上限兜底）。
  可用 `watch_auto_unwatch_on_kick` 关掉，关掉后仅记录日志。
- **平台限制**：比赛推送依赖「机器人主动发消息」的能力。QQ 官方机器人等通道
  不支持主动消息，添加监听时会直接给出警告。

数据会落盘在 `AstrBot/data/plugin_data/astrbot_plugin_dota2/bindings.json`，
重启后监听关系依然有效。

### 模型自检

```
/d2 模型测试                     # 自检专用 API Key 通道是否可用
```

用一次极短请求探通模型通道，回显接口地址、模型名、耗时；失败时给出具体错误
（HTTP 状态码 / 连接情况）和对应的排查建议。没配专用 Key 时会说明当前走的是
AstrBot 提供商，并实测一次该通道。

### 数据源自检

```
/d2 数据源                       # 自检主/后备数据源的连通性与降级状态
```

会逐项回显：当前谁是主源谁后备、每个源是否可用（附英雄表条数与耗时）、本次运行
期间有没有发生过降级、最近一次降级的原因。没配 STRATZ Key 时会直接说明「STRATZ
通道被跳过，全部走 OpenDota」并给出申请入口。

## 数据源：STRATZ 主 + OpenDota 后备

插件默认使用 **双数据源**：以 [STRATZ](https://docs.stratz.com/) 为主数据源、
OpenDota 作为后备。主源失效时自动切后备，无需人工干预。

为什么用 STRATZ 做主力：

- **经济数据一次拿全**：GPM / XPM / 正补 / 反补 / 英雄伤害 / 塔伤 / 治疗 这些字段
  单次查询就全带回来。OpenDota 的 `/players/{id}/recentMatches` 只有最近 20 场
  包含经济数据，所以 `/d2 分析 40` 时常常只有 20 场有 GPM —— 换上 STRATZ 后
  这个限制消失；
- 官方 Schema 稳定（GraphQL），字段有文档可查。

### 启用 STRATZ（可选）

不填 Key 也能正常用：插件会检测到 STRATZ 未配置，**所有查询直接落到 OpenDota**，
行为与升级前完全一致。

想启用 STRATZ：

1. 打开 <https://stratz.com/api>，用 Steam 登录后点 **Generate Token**；
2. 把令牌填进插件配置的 **「STRATZ API Key」**（`stratz_api_key`）；
3. 发一次 **`/d2 数据源`** 确认主源已就绪。

免费 Default Token 的额度约为 **20 次/秒、250 次/分、2000 次/时、10000 次/天**，
远超本插件的实际用量。

### 降级行为

**同一次查询只会命中一个数据源。** 每个方法都是「先试主源，主源抛不可用类异常
才切后备」——不是两边都拉一遍再对比，所以一次查询里不会混用两个源。

> 唯一的例外是「主源在一次查询中途挂掉」：例如 `get_match` 走 STRATZ 成功、
> 紧接着 `get_heroes` 时 STRATZ 抖动，此时英雄表会来自 OpenDota。这两张都是
> 「id → 名字」常量表，两个源内容等价，语义上无害，因此**有意保留**这种降级，
> 而不是让整次查询失败。

| 主源情况 | 插件的动作 |
|----------|------------|
| 未配置（没填 Key） | 直接走后备，不做无谓尝试，**不算降级** |
| 鉴权失败（401/403） | 切后备，日志记一条 warning |
| 限流（429） | 先分类重试（指数退避），重试耗尽后切后备 |
| 网络超时 / 连不上 | 分类重试后切后备 |
| 找不到玩家 / 昵称歧义 | **不降级** —— 换数据源也查不到，如实报给用户 |
| 后备也失败 | 如实向上抛错，由指令层给出提示 |

### 解析状态的统一口径

比赛是否「已解析」由 `dota_format.parsed_state()` **统一判定**，两个数据源共用：

| 数据源 | 逐分钟产物 |
|--------|-----------|
| OpenDota | 每名玩家的 `gold_t`（逐分钟金钱） |
| STRATZ | 比赛级 `radiant_gold_adv` / `radiant_xp_adv` 曲线 |

只要其中之一存在，就判为「已解析」。因此标题行与 AI 提示词正文给出的完整度
说明**永远一致**，不会出现「标题说已解析、正文说未解析」这种自相矛盾。

数据源没给的字段会渲染成 `-`（或「不可用」），**不会伪装成 `0`**——例如未解析
时没有团战数据，质量块会写「团战数据: 不可用」而不是「团战次数: 0」。

几点注意：

- **STRATZ 令牌绑定出口 IP**：官方把令牌绑定到首次调用的 IP，换网络后会**临时
  返回 403**（`You cannot use different IP Addresses when using the API.`）。
  插件能单独识别这个信号并重试（不是永久失败）；持续失败才降级。国内服务器建议
  配合 `http_proxy` 使用固定出口；
- **催解析只走 OpenDota**：STRATZ 不支持主动提交解析任务，`/d2 催解析`、
  单场等待解析流程固定使用 OpenDota，不受主源影响；
- 在配置里把 **「数据源优先级」** 改成 `opendota`，可以让两者对调
  （OpenDota 主 / STRATZ 后备）。

## 用你自己的模型跑报告（可选）

默认情况下，AI 报告用的是 AstrBot 里配置的模型。如果你想让 **Dota2 插件的报告单独走一个通道**
（例如换成更便宜的 `deepseek-chat`，而机器人闲聊仍用原来的模型），在插件配置里填
「插件专用 API Key」即可。

三步搞定：

1. **填 Key**：`llm_api_key` = 你的 API Key；
2. **填地址**：`llm_base_url` 可以直接填服务商名（会自动补全），也可以填完整 base_url：

   | 服务商名 | 实际地址 |
   |----------|----------|
   | `deepseek` | `https://api.deepseek.com/v1` |
   | `kimi` / `moonshot` | `https://api.moonshot.cn/v1` |
   | `qwen` / `dashscope` | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
   | `zhipu` / `glm` | `https://open.bigmodel.cn/api/paas/v4` |
   | `siliconflow` | `https://api.siliconflow.cn/v1` |
   | `openrouter` | `https://openrouter.ai/api/v1` |
   | `ollama` | `http://127.0.0.1:11434/v1` |

   中转站 / 自建网关直接填完整地址（到 `/v1` 为止，不要带 `/chat/completions`）。
3. **填模型名**：`llm_model`，例如 `deepseek-chat`、`gpt-4o-mini`、`qwen-plus`。

填完在群里发 **`/d2 模型测试`** 自检一次，会回显接口地址、模型名、耗时，失败时给出具体错误和排查建议。

行为约定：

- 只对「分析 / 单场」的报告生效（监听推送的短评另有一套内置提示词，
  可用 `watch_comment_system_prompt` 单独调整）；自然语言的意图识别仍用 AstrBot 默认模型；
- 配了专用 Key 但调用失败时，默认自动回退到 AstrBot 的模型重试一次（可用
  `llm_fallback_on_error` 关闭）；
- 不填专用 Key 时行为与以前完全一致，不影响现有部署；
- 只依赖 Python 标准库实现，不新增第三方依赖。

## 数据来源与已知限制

- 数据全部来自 OpenDota 公共 API，**不需要 Steam API Key**。
- OpenDota 对局数据本身有延迟（通常落后官方几分钟到一小时），监听推送天然存在时延。
  好在监听短评只要胜负与 K/D/A，比赛一被收录就能发，不必再等录像解析。
- **解析数据需要申请**：逐分钟经济、团战、出装日志等来自录像解析。未解析的比赛只有基础统计。
  插件会自动提交解析任务（`POST /request/{match_id}`，该接口按 10 倍额度计费），
  但解析队列可能排队较久。**监听短评不依赖它**（因此也不会为监听去申请解析）；
  单场深度复盘遇到未解析的局会自动「催 + 等」（见上方「催解析 + 等待解析」章节），
  最多等 10 分钟；想跳过等待用 `/d2 单场 <比赛ID> skip`。
- **`od_data` 是状态对象，不是「已解析」标志**：`/matches/{id}` 返回的
  `od_data = {has_api, has_gcdata, has_parsed, has_archive}` 只要比赛被收录就存在。
  判断是否解析完成要看 `has_parsed`（或玩家级 `gold_t` 是否被填充）；
  `has_gcdata = false` 表示 OpenDota 连游戏客户端数据都没拿到，属未解析。
- **主动推送依赖平台能力**：比赛结束后的推送需要机器人能主动发消息。QQ 官方机器人等
  通道不支持主动发送消息，此时添加监听会给出警告，推送也无法送达；这类场景建议改用
  `/d2 单场 <比赛ID>` 手动复盘。
- 玩家需在 Dota 2 设置中开启「公开比赛数据（Expose Public Match Data）」，否则查不到比赛。
- **两个数据源的「解析产物」覆盖范围不一样**：上面那批逐分钟、经济来源、伤害构成、
  视野日志等字段目前只有 **OpenDota** 提供（它把录像解析结果全量返回）；STRATZ 的
  `MatchPlayerType` 字段集要窄得多。因此：
  - 走 STRATZ 主源时，提示词里这些进阶小节省略，报告会基于 STRATZ 给的字段（KDA、
    GPM/XPM、补刀、伤害、分路、位置、出装、经济/经验曲线、BP）来写；
  - 想要最完整的复盘数据，让该局走 OpenDota 通道即可（不配 STRATZ Key，或该局
    STRATZ 没收录时会自动降级到 OpenDota）。
- **金币/经验来源的键名表按 Valve 官方枚举**（`EDOTA_ModifyGold_Reason` /
  `EDOTA_ModifyXP_Reason`）。注意网上流传的 YASP 旧表把 `14` 写成「肉山」、`15`
  写成「信使」，与现行引擎不符（实测 `14` 与野怪击杀数相除恒为 50~70 金币/只，
  `17` 则同队五人完全相等，正是赏金符的均分特征），插件按官方枚举标注。
- **`lane_efficiency_pct` 与 `lane_efficiency` 量纲不同**：前者是百分数（`119` 表示
  119%），后者是比率（`1.19` 表示 119%）。插件统一按百分比渲染，不会再出现「11900%」。
- **塔/兵营的状态位掩码是「置位 = 还活着」**：`tower_status_*` / `barracks_status_*`
  里置位的含义是该建筑**仍在**（`0x7FF` = 11 座塔全在，`0` = 全丢）。插件换算成
  「丢 x/11（剩 y）」这种人类口径。这条口径用两条独立字段互证过：同一局的
  `tower_status` 置位数与 `objectives` 里 `building_kill` 事件的累计数完全吻合
  （曾把方向写反，症状是汇总说「夜魇塔完好」而时间轴却在拆夜魇塔）。
- **`objectives` 里兵营的键名是 `melee_rax` / `range_rax`**（如
  `npc_dota_goodguys_melee_rax_bot`），不是 `rax_melee`；`goodguys` = 天辉、
  `badguys` = 夜魇，`fort` 是基地。
- OpenDota 的 `/search`（昵称搜索）偶发响应缓慢，插件为其单独放宽了超时；
  若持续失败，请直接使用账号 ID 绑定。
- 英雄名使用 OpenDota 提供的英文名（如 `Luna`、`Nature's Prophet`）。
- **经济数据 20 场上限只在 OpenDota 通道存在**：`/players/{id}/matches` 只返回 KDA
  等基础字段，GPM/XPM/补刀/伤害等字段来自 `/players/{id}/recentMatches`，而后者
  **最多只有 20 场**。启用 STRATZ 主源后该限制消失（STRATZ 单次查询即带全部经济
  字段）；仍走 OpenDota 时，超出 20 场的部分没有经济类字段，聚合统计里会自动标注
  可用样本数。

## 文件结构

```
astrbot_plugin_dota2/
├── main.py              # 插件入口：指令注册、事件处理、监听后台任务、数据源组装
├── dota_api.py          # OpenDota 异步客户端 + FallbackDataSource（主/后备降级）

├── dota_nlu.py          # 自然语言意图识别（规则优先，可选大模型兜底）
├── dota_chat.py         # 闲聊兜底：把插件内部数据整理成模型上下文
├── dota_store.py        # 绑定与监听关系的落盘读写
├── dota_format.py       # 原始数据 → 可读文本 / 结构化提示词素材
├── dota_analyzer.py     # 提示词构造 + 大模型调用
├── _conf_schema.json    # 插件配置 Schema
├── metadata.yaml        # 插件元数据
└── requirements.txt
```

## 开发自测

仓库根目录的 `tests/` 提供一组不依赖真实 AstrBot 的验证脚本（`run_selftest.py`
会真实访问 API，其余使用替身）：

```bash
python tests/run_selftest.py         # 端到端跑通全部指令与监听推送链路
python tests/watch_logic_check.py    # 监听核心逻辑的行为断言（不联网）
python tests/unit_check.py           # 纯函数单测
python tests/focus_check.py          # 单场「焦点玩家深入数据」（含多焦点）与提示词校验
python tests/event_takeover_check.py # 事件接管（直发 + 终止传播）的行为校验
python tests/nlu_check.py            # 自然语言入口：意图识别 + 端到端分发
python tests/nlu_chat_check.py       # 闲聊兜底：数据注入路由、缺失不冒充、失败必放行
python tests/takeover_scope_check.py # 放弃消息时不得吞掉其他插件与默认大模型
python tests/parse_wait_check.py     # 催解析 + 等待解析：成功 / 超时 / 跳过 / 并发
python tests/watch_deliver_check.py  # 监听短评：标题推进基线、正文失败可见、不再 @ 人
python tests/llm_channel_check.py    # 专用模型 API Key：地址归一 / 返回体解析 / 回退优先级
python tests/fallback_check.py       # 主/后备数据源：降级触发、不降级情形、插件组装
python tests/stratz_client_live.py   # STRATZ 客户端真实 API 验证（需在文件内填 Key）
python tests/od_data_probe.py        # 真实拉取指定比赛的 od_data，探查解析状态
```
